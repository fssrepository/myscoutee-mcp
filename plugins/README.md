# Plugin packages (unpublished)

`myscoutee/` owns plugin metadata and MCP configuration. The skill's only source is
`myscoutee-skills/.agents/skills/myscoutee/SKILL.md`; keep that checkout beside this
repository or its parent application repository (see `AGENTS.md`). `build.py`
includes it in each target package without duplicating the authoring source or
MCP implementation. No command here installs, publishes or changes a marketplace.

Publication continuation: [PUBLICATION_HANDOFF.md](PUBLICATION_HANDOFF.md).
The current archives are development artifacts, **not submission-ready**.
Policy content, reviewer access, recording, targeting and live host checks remain
open; the handoff separates these from completed source preparation.

```sh
# From the MCP repository root: build both local Docker/stdio packages.
make plugin
make plugin PLUGIN_TARGET=claude
make plugin PLUGIN_TARGET=openai

# After editing the portable manifests, synchronize tracked compatibility files.
make plugin-sync
# Every build validates the resulting ZIP. Recheck an existing artifact:
make plugin-check PLUGIN_ZIP=build/myscoutee-plugin-openai-local-1.4.1.zip
# Strict preparation gate: exits nonzero and lists missing review material.
make plugin-check PLUGIN_ZIP=build/myscoutee-plugin-openai-local-1.4.1.zip SUBMISSION=1

# Remote anonymous-help packages: replace with your deployed public endpoint.
make plugin MCP_URL=https://your-deployment.example/mcp
# Personal OAuth variant (configure client ID/secret separately in the client).
make plugin MCP_URL=https://your-deployment.example/mcp/private

# Match the application's existing release version input.
MYSCOUTEE_VERSION=1.4.1 make plugin PLUGIN_TARGET=openai MCP_URL=https://myscoutee.com/mcp/private
```

Outputs: `build/plugins/{openai,claude}/{local,remote-help,remote-private}/myscoutee/` and
`build/myscoutee-plugin-{target}-{variant}-{version}.zip`. The version comes from
the application's `MYSCOUTEE_VERSION` release input, or the common manifest when
no release input is supplied (currently 1.4.1). Both platform manifests, the ZIP
filename, release-note version prefix and local Docker reference use that value.
The existing `make image` target uses the same release input for its image tag;
build that image before using a local package. Release overrides do not rewrite
tracked authoring files or change an already deployed server. The MCP binary's
own component version remains independent from this application release number.
Build does not bundle credentials or the server image.

`plugin.json` and `mcp.json` are canonical. The Codex overlay and `.mcp.json`
are generated by `plugin-sync`; builds reject stale copies. ZIP checks cover
identity/version, transport agreement, Docker tag, referenced PNG files, listing
limits, review cases, placeholder URLs and public-upload exclusions. They do not
verify remote content, OAuth, marketplace acceptance or a recorded demo.
The remote-help variant uses its own five positive/three negative cases from
`review/remote-help.json`; private cases live in the canonical manifest.

| Target | Manifest | Distribution |
| --- | --- | --- |
| OpenAI | Root `plugin.json` + `mcp.json`, Codex compatibility overlay | ChatGPT/Codex plugin submission; public MCP submissions require a deployed HTTPS endpoint |
| Claude | `.claude-plugin/plugin.json` + `.mcp.json` | Claude Code plugin directory/package; subsequent marketplace publication is separate |

The local package needs Docker, the locally built `myscoutee-mcp:1.4.1` image and
the API URL/key/client-ID environment variables described in the main README.
The remote-help package exposes anonymous help. The remote-private package
uses the profile-owned OAuth connection created under the app’s API keys.
Remote URL-based OAuth uses automatic registration and MyScoutee login/approval.
For predefined clients, generate credentials under Advanced and configure them
outside the package; see the main README. A Claude Code
plugin ZIP does not imply claude.ai connector-directory approval.

Both packages include the existing MyScoutee app logo in `assets/logo.png`.
OpenAI's `logo` and `composerIcon` fields reference it. Claude's documented plugin
manifest has no logo field; use the bundled image wherever the publication UI
accepts a logo rather than adding an unsupported manifest field.

For local validation, use the target's plugin validator. For OpenAI, register the
real MCP endpoint and follow the submission flow; do not put fabricated
`plugin_asdk_app` IDs into the package. Live client installation and store approval
are not covered by the package build.
